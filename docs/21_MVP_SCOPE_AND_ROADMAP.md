## 0. MVP 核心判斷

### 0.1 MVP 必須證明什麼

MVP 只驗證三件事：

1. **戰鬥手感成立**：Ghost 移動、普攻、Dash、受擊、死亡都能玩。
2. **能力奪取成立**：打敗 Boss 後真的拿到一招可用技能。
3. **相剋爽感成立**：上一位 Boss 掉落技能，能明顯破解下一位 Boss 或其關卡小怪。

如果這三件事不成立，做再多 Boss、UI、音樂、道具都只是堆料。

### 0.2 MVP 一句話

```text
玩家操控 Ghost 通過教學地圖，擊敗 M先生取得管線衝擊，再用管線衝擊破解滅影忍者的分身與隱身。
```

### 0.3 MVP 成功條件

| 成功條件 | 驗收方式 |
|---|---|
| 玩家能在 1 分鐘內理解操作 | 不看說明也能移動、攻擊、Dash。 |
| M先生 Boss 戰能完成 | 有清楚攻擊前搖、破綻、勝利。 |
| 打敗 M先生後解鎖管線衝擊 | 玩家可立即施放。 |
| 管線衝擊能破解影系敵人 | 分身碎裂、隱身現形、有破防提示。 |
| 滅影忍者戰因管線衝擊變得可讀 | 玩家感覺「我有答案」。 |
| 死亡後能重開 | 不需要長讀取或複雜流程。 |
| 一局 10～20 分鐘內結束 | 手機 / Web Prototype 節奏明確。 |

## 2. MVP 玩家體驗流程

### 2.1 首次遊玩流程

```text
首頁
  ↓
開始遊戲
  ↓
怨念甦醒地：教移動 / 普攻 / Dash
  ↓
小怪戰：碎運鬼 / 黑運糰
  ↓
紅帽管線城：水管工僕 / 噴氣水管兵
  ↓
M先生 Boss 戰
  ↓
擊敗 M先生，奪取管線衝擊
  ↓
影村訓練場：影紙忍 / 飛鏢影童 / 假身木樁
  ↓
玩家用管線衝擊震出分身與隱身
  ↓
滅影忍者 Boss 戰
  ↓
擊敗或死亡結算
```

### 2.2 第二局體驗

第二局應讓玩家感覺：

- 更懂 M先生的跳砸節奏。
- 知道管線衝擊要留給分身 / 隱身。
- 會選能強化管線衝擊或 Dash 的遺物。
- 想嘗試更快通關或少受傷。

## 5. MVP 技能範圍

### 5.1 Ghost 基礎能力

| 能力 | 必做 | 說明 |
|---|---|---|
| 移動 | 是 | 手感第一優先。 |
| Dash | 是 | 短距離位移 + 短無敵。 |

### 5.2 管線衝擊

必做效果：

- 前方地面震波。
- 擊退小怪。
- 打破分身。
- 震出隱身。
- 命中有黑紫地裂 VFX。
- 冷卻與怨念消耗。

可延後：

- 震波反彈。
- 地裂延遲爆炸。
- 多段升級。

### 5.3 影遁衝刺

在 MVP 結尾可先做解鎖，不一定完整加入下一關。

必做方向：

- 短無敵位移。
- 黑影殘影。
- 穿越直線攻擊。
- 第二階段用來克制 U-man。

| 震盪怨骨 | Rare | 撞牆追加傷害。 |
| 分身驗屍單 | Rare | 擊殺分身降冷卻。 |
| 遲到的主角光環 | Epic | 完美 Dash 回怨念。 |

| 假主角光環 | Survival | 低血量一次護盾。 |

### 7.2 三選一規則

MVP 三選一先做簡化：

```text
每通過 1～2 個房間出一次三選一。
Boss 後必出一次技能相關選項。
每次至少 1 個和目前技能有關。
```

### 7.3 重骰

MVP 可先不做重骰，或只在商店提供一次。

## 12. 開發階段 Roadmap

## Phase 0：專案基礎與設計鎖定

目標：把所有核心文件、資料結構與 Prototype 技術選型固定。

任務：

- 完成 `docs/01～21` 設計文件。
- 決定引擎：Godot / Web / 其他 2D 技術。
- 建立基本專案結構。
- 建立素材資料夾。
- 建立資料表格式：skill / enemy / boss / relic / stage。
- 確認輸出平台：Web Prototype 優先，後續再看 Android。

完成標準：

```text
能清楚知道第一版要做什麼、不做什麼、資料怎麼放、素材怎麼命名。
```

不需要 Boss，也能在測試房間裡打小怪 3 分鐘，手感不痛苦。

## Phase 6：第二輪內容擴充

目標：在 MVP 成立後擴充到 3～4 位 Boss。

優先順序：

1. U-man。
2. 鋼筋戰士。

- U-man 可驗證影遁衝刺穿光束。

- 葫蘆爺可驗證破甲合擊打斷吸收。

完成標準：

```text
至少形成 3 段以上能力相剋鏈，而不是單次教學。
```

## 15. 技術選型建議

### 15.1 Web Prototype 優先

優點：

- 分享測試最快。
- GitHub Pages / itch / Replit 類平台容易展示。
- 修改速度快。
- 適合先驗證手感與核心循環。

缺點：

- 手機效能與觸控要額外測。
- 資產管理與複雜動畫需規劃。

### 15.2 Godot 優先

優點：

- 2D 動作遊戲適合。
- 打包 Android / PC 較完整。
- AnimationPlayer / Area2D / TileMap 都可用。
- 適合長期完整遊戲。

缺點：

- 一開始需要建工程結構。
- 若美術資產還不穩，導入調整時間較多。

### 15.3 建議策略

```text
先用最快的方式做可玩 Prototype。
如果核心爽感成立，再轉 Godot 或整理成正式工程。
```

不要在核心戰鬥還沒成立前，花太多時間做完整工程架構。

## 17. 風險與對策

### 17.1 戰鬥手感不好

風險：玩家不想繼續玩。

對策：

- 先做灰盒，不等美術完成。
- Dash、普攻、受擊優先調整。
- 加 hit stop、擊退、閃白。

### 17.2 相剋不明顯

風險：玩家感覺 Boss 技能只是多一招。

對策：

- 相剋命中時加專屬破防動畫。
- UI 顯示「氣運破裂」。
- 小怪先教一次，再放 Boss。

### 17.3 內容太多做不完

風險：專案進入無限設計。

對策：

- MVP 只做 M先生與滅影忍者。
- 其他 Boss 只保留設計文件。
- 每週只驗收可玩項目。

### 17.4 美術生成不一致

風險：角色風格混亂。

對策：

- 先鎖定 Ghost / M先生 / 滅影忍者三個主素材。
- 使用 `06/07/08/19` 規格控制 prompt。
- 先白底動作表，再切圖。

### 17.5 音效與特效太吵

風險：手機畫面和聽覺混亂。

對策：

- SFX 分優先級。
- Boss 大招提示最高優先。
- 普通小怪 SFX 共享變體。
